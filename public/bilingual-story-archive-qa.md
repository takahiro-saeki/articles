VOLT NOMADには日英33イベントの会話カタログと、校正用Markdownを作るスクリプトがあります。固定版から再生成すると33イベント・101行の会話を確認できました。ただし、関数呼び出しを改行するだけで、イベント数は変わらず会話が1行抜けることも再現しました。

確認表の「33件」という表示に加えて、各行をゲームが読むデータと照合します。

## ゲーム側の正本と校正表の役割

対象は`game-jam-lab`のcommit `f074703`です。[story_catalog.gd](https://github.com/takahiro-saeki/game-jam-lab/blob/f074703848586828b6a5acc0e465ccdd2c0d5244/events/2026-ai-browser-game-jam-4/godot/games/charge_clicker/story_catalog.gd)にイベントID、日本語・英語の題と状況、話者、台詞があります。`line(...)`が同じ一行へ両言語を入れる形式です。

[export-dialogue-review.mjs](https://github.com/takahiro-saeki/game-jam-lab/blob/f074703848586828b6a5acc0e465ccdd2c0d5244/events/2026-ai-browser-game-jam-4/tools/export-dialogue-review.mjs)は、そのカタログとゲーム本体を読み、`docs/VOLT_NOMAD_TEXT_REVIEW.md`を生成します。校正表の変更がゲームへ自動反映される仕組みではなく、修正先の正本はGDScriptです。

イベントディレクトリ内での生成コマンドは次のとおりです。

```sh
node tools/export-dialogue-review.mjs
```

今回の実行では、固定commitから必要なソースを一時ディレクトリへ取り出して起動しました。元の作業ツリーや生成済み文書は変更していません。

## 正規表現の出力をGodotの実データと照合する

2026年9月11日、Node.js 24.15.0で元の生成スクリプトを動かしました。独立した確認先として、Godot 4.6.2のheadless実行で元のカタログを読み、`EVENTS`の内容をJSONへ出しています。

| 確認した内容 | 結果 |
| --- | ---: |
| 会話イベント | 33件 |
| 会話イベント内の台詞 | 101行 |
| 戦闘中の短い通信の区分 | 12戦 |
| 短い通信の表の台詞 | 33行 |

33イベントについて、ID、日英の題と状況、全101行のrole・話者・台詞を校正表と照合し、一致しました。生成処理が行う`|`のエスケープと改行の`<br>`変換も、照合時に揃えています。

短い通信の12戦・33行は生成表の集計です。会話カタログの101行とは別で、通信側を同じGodotデータとして照合した結果ではありません。この集計値と、実データの一致確認は分けて扱います。

## カタログの検査が、欠落や重複を検出するか

元の`validate()`は、イベントIDの重複や、題・状況・台詞などの必須値を調べます。この実装をそのままGodotで動かしたところ、固定版のエラーは0件でした。

その後、メモリ上だけで次の3条件を作り、それぞれ1件のエラーになることを確認しました。

- 同じイベントを一つ追加してIDを重複させる。
- 最初の台詞の英語本文を空にする。
- 最初のイベントの英語タイトルを空にする。

各条件の後で元データへ戻しています。試験のためにゲームの正本を壊したわけではありません。

この検査が扱うのは値の存在や重複です。翻訳の意味、口調、伏線が正しいかを判定するものではありません。同じIDの日本語と英語を並べる校正表は、その人による確認を支えます。

## 意味の同じ改行で、確認表から1行抜けた

生成スクリプトは`line(...)`呼び出しを一行に書くことを前提とする正規表現です。実際に、最初の呼び出しの引数途中へ改行を入れました。

Godotが読み出したカタログは変更前と完全一致し、元の検査も通りました。一方、再生成した会話表は101行から100行へ減りました。イベントIDは残るため、見出しの33イベントという数は欠落を検出しません。

| 見る場所 | 改行後 |
| --- | --- |
| Godotが読むデータ | 変更前と一致 |
| カタログの検査 | 通過 |
| 校正表のイベント見出し | 33件 |
| 校正表の台詞 | 100行 |

したがって、生成スクリプトの成功終了だけでは全文を取り出した保証になりません。現行データでの全行照合を維持するか、将来はGodotから出力した構造化データを校正表の入力にする設計が考えられます。後者はこの記事で製品へ導入した変更ではありません。

## テキストの一致と、ゲーム画面での確認を分ける

[会話の設計資料](https://github.com/takahiro-saeki/game-jam-lab/blob/f074703848586828b6a5acc0e465ccdd2c0d5244/events/2026-ai-browser-game-jam-4/docs/VOLT_NOMAD_STORY_EVENTS.md)と本体コードには、開発ビルドのStory Lab、プレイヤー向け会話記録、ローカルWeb用の全件表示が用意されています。`story_archive=all`の分岐ではローカルhostを判定し、ゲーム進行の保存を無効にしてから会話記録を開くコードを確認しました。

これらは、英語の折り返し、日英切替、送りとスキップ、未回収イベントの表示を画面で確認するための入口です。今回実行したのはカタログと校正表の照合であり、全ゲームの起動、Webリリースの書き出し、全33イベントの画面確認は行っていません。保存無効化のコード確認から、実ブラウザで保存が変化しないことまで証明したとは扱いません。

[再現と照合コード](https://github.com/takahiro-saeki/articles/blob/codex/article-stock-2026-09/experiments/article-stock-2026-09/game-records-batch12.py)には、正常データ、3つの検査用変更、改行による抽出漏れを残しています。全文の校正は、まず確認表が全文を含むことを確かめ、その後に意味と表示を読む順序にします。
