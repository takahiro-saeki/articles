生成画面で良く見えたピクセルキャラクターが、ゲームへ入れると背景に埋もれることがあります。輪郭、サイズ、アニメーション速度が、実際のカメラ倍率や敵との並びで変わって見えるためです。

Nocturne Vaniaでは、候補を画像一覧だけで決めず、Godot上で切り替えて試遊できる仕組みと、Pixel Studioのレビュー状態を組み合わせています。

## 主人公候補を実行中に切り替える

主人公スキンは定義を分け、デバッグ入力のF8で候補を順番に切り替えます。

```gdscript
var current_skin_index := 0

func cycle_skin() -> void:
    current_skin_index = (current_skin_index + 1) % skins.size()
    apply_skin(skins[current_skin_index])
```

シーンを作り直さず、同じ部屋、同じ入力、同じ敵で比較できます。立ち絵だけでなく、走る、ジャンプする、攻撃する、ダメージを受ける場面まで確認します。

## look-dev用の部屋を持つ

キャラクター以外の素材は`look_dev.tscn`へ並べます。背景色、床、ライティング、カメラ倍率を本編に近づけ、複数候補を同じ条件で表示します。

確認する内容は素材ごとに違います。

- キャラクターはシルエットとアニメーションの読みやすさ
- エフェクトは背景上のコントラストと表示時間
- タイルや小物は繰り返したときの継ぎ目と密度

画像単体の美しさより、ゲーム内で役割を読めるかを見ます。

## レビュー状態をゲーム実装と分ける

Pixel Studioでは素材を`review`、`adopted`、`rejected`へ変更できます。採用を押しても外部サービス上の画像は削除せず、レビュー状態だけを保存します。

実際に`assets`へ配置し、manifestへpathが登録された素材は`implemented`として照合できます。人の判断と、リポジトリ上の実装事実を混ぜないためです。

```json
{
  "sourceKey": "history:hero-v3",
  "assetPath": "assets/player/hero_v3",
  "status": "implemented"
}
```

## 比較条件を固定する

候補Aと候補Bを別の場面で見ると、素材以外の差に引っ張られます。切り替え機能ではプレイヤー位置、カメラ、敵、入力を維持したまま見た目だけを変えます。

採用後も以前の候補を残しているため、違和感が出たときに戻して比較できます。生成コストより、採用判断をやり直せることを優先しました。

AI生成素材は候補を増やしやすい反面、選ぶ工程が詰まりやすくなります。ゲーム内比較、レビュー状態、実装manifestを分けると、「生成済みだが未確認」「採用したが未実装」という途中状態を見失いません。

記事公開時には、主人公候補の切り替えGIFとlook-dev画面の比較画像を追加する予定です。
