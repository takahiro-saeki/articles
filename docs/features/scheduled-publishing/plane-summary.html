機能ID: scheduled-publishing。Project: articles (ART)、Workspace: hiro-work。最終確認: 2026-10-08。

公開スケジュール

日本語は1日1本、09:00 JSTを目標に公開する。Zennは毎週土曜1本、次回は10/17。その他の日はQiita。dev.toは対応する日本語の実公開を確認してから公開・更新する。

日次運用

  1. GitHub Actionsのpublish-scheduled.ymlが当日の日本語を公開し、公開API・認証なし実ページを確認する。
  2. 続いてdev.toを公開する。既存英語版はIDを維持し、日本語の実URLへcanonicalを更新する。
  3. Gitのpublication-state.jsonに両言語のURL、ID、verifiedを保存する。原稿完成・公開フラグ・Actionsの緑表示だけでは公開完了としない。
  4. このチャットの定期実行「記事公開の点検・回復」が毎日09:30・13:30 JSTに当日分と未解決分を点検する。両言語とcanonicalの照合後にPlaneの対応チケットをDoneにし、確認日時・公開URL・runを残す。異常と回復、全件完了を通知する。

遅延・失敗時

同じ記事のrunが実行中なら重複dispatchしない。未開始・失敗時は公開先と保存済みIDを確認して既存workflowを対象予約日で再実行する。API成功とID保存が不明なまま新規作成を繰り返さない。未来日の先行公開、Zennの土曜以外の新規公開、週1本制限の解除は行わない。

Zennの投稿数上限や状態不明で回復できなければ、失敗を残して後続への影響を報告する。GitHub Actionsには予約の遅延があり、09:00ちょうどの公開は保証できない。追加の定期点検はPCとCodexアプリの起動が必要。自動投稿自体はGitHub Actionsで実行される。点検は12/15の最終確認まで設定した。
